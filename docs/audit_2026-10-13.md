# Independent audit: joint R/C kinematics, 2026-10-13

The initial-condition concern is justified. The original optimizer barely moved
the rotation amplitude, and the current pipeline still has both optimization
defects and an uncalibrated statistical model. Increasing the learning rate was
useful, but does not establish accurate rotation speeds, detections, or masses.

This review compared the original Yichen notebooks and package, the October 13
handoff and saved results, the current package, all three supplied papers, and
the local EDR products. New numerical checks used existing real observations;
no new simulated observations or production MCMC chains were generated.

The requested science product is **deprojected rotation and mass profiles over
the observed radii**. The immediate priority is to distinguish numerical
dependence on starting points from actual lack of information in those profiles.

## What is confirmed

### 1. The original amplitude was effectively tied to its initialization

In `archive/2026-10-12/yichen_codes/1.1-astr540-plot.ipynb`, cell 18 starts each
source at signed 300 km/s and runs 500 Adam steps. It specifies
`velocity.v_rot: {lr: 1}`, whereas the registered name is `velocity.V_rot`.
The saved notebook output explicitly warns that this override is unused.

Examples of its actual outputs:

| Source | Initial V_rot | Returned V_rot, km/s |
|---|---:|---:|
| 3700 | -300 | -310.76 |
| 15665 | -300 | -312.73 |
| 16887 | 300 | 299.18 |
| 21636 | 300 | 316.19 |

With Adam, parameter scaling and learning rate matter even when a gradient is
large. The intended amplitude-specific rate was never applied. The current
code correctly rejects unused overrides and gives the amplitude a larger rate.
Those repairs should stay.

However, the handoff's own `logs/lr_fix.out` shows that a larger rate does not
remove initialization dependence. For ID3700, at rate 5 the five starts
50/200/400/700/1100 finish at -16/436/435/518/1126 km/s. For ID15665, similar
amplitudes near 275 can still have substantially different losses. Agreement
of one parameter does not establish agreement of the full fitted state.

### 2. Repeating fit_all silently froze the position angle

`BaseFitter.fit_all()` shares parameter tensors between stages. The last stage
sets `theta_v.requires_grad=False`. On a second call, stage zero selected its
configuration with `fit=True` but did not restore the gradient flag. The
optimizer included the parameter but received no gradient for it.

A short check on ID3700's actual input data, using only three steps per stage,
reproduced this before the repair:

| Pass and stage | fit flag | requires_grad | Angle before / after |
|---|---|---|---|
| First, stage 0 | True | True | 0 / 0.150224 |
| First, stage 1 | False | False | 0.150224 / 0.150224 |
| Second, stage 0 | True | **False** | 0.150224 / 0.150224 |

Explicitly enabling the gradient gave a nonzero derivative, approximately
-0.0215. This was not a stationary angle. These are diagnostic steps, not a
new scientific fit.

**Fixed:** `fit_gradient()` now applies the active stage's flags on every entry.
A regression test changes a known optimum between calls and verifies that the
previously frozen parameter moves again.

This invalidates the claim that `HANDOFF.../code/converge.py` tested repeated
full optimization. Its later passes optimized a different parameter subset.
That script also stops when a loss *increases*, because its stopping condition
is `prev - L < tolerance`; an arbitrary worsening satisfies it. The archived
script was preserved rather than edited. Its conclusions need re-evaluation.

Simply raising `maxiter` is not equivalent to restarting: restarting resets
Adam's moments and learning-rate schedule. It is premature to call 7500 steps
the established solution.

### 3. The multistart winner lost its fitted registration offsets

`startpoint.find_start()` previously returned and saved only velocity
parameters, although each refinement also fitted the R registration offsets.
The clean notebook rebuilt a fitter from that incomplete state, resetting the
offsets. This changed the starting point before the next optimization.

**Fixed:** every trial now contains `full_params`, including the offsets. The
clean notebook restores that snapshot. The existing return tuple remains
compatible. The returned score is now evaluated at the actual final parameters;
the last recorded optimizer loss preceded its final update and clamp.

A real-data regression test restores a winning trial into a fresh fitter and
reproduces its score. Archived drivers that copy only the velocity dictionary
still need to adopt `full_params` before reuse.

### 4. The clean notebook used the wrong speed for enclosed mass

It computed `M5 = V_rot**2 * 5 kpc / G`, although `V_rot` is the asymptotic
amplitude. The model instead requires

\[
 V(r)=\frac{2}{\pi}V_{\rm rot}\arctan(r/R_v),\qquad
 M_{\rm rot,eq}(<r)=V(r)^2r/G.
\]

For the saved ID3700 parameters, `R_v = 2.420 kpc`; the correct expression at
5 kpc is 0.5084 times the old expression: the old expression overstates it by
1.97 times, or 0.294 dex. For ID15665 the excess is 0.255 dex. These comparisons
hold the saved parameters fixed and are not newly validated galaxy masses.

**Fixed:** a shared array-capable helper in `dingo/utils.py` evaluates the
rotation curve first, and the clean notebook calls it with matched posterior
samples of amplitude and radius. A test checks the analytic turnover-radius
case, where the speed is half the asymptotic value and the mass is one quarter.
The original student's mass function already included the arctangent factor;
this omission was in the newer clean notebook.

This quantity is a rotation-only, spherical-equivalent mass estimator. Disk
geometry and pressure support require explicit scientific assumptions. The
SAPPHIRES demonstration adds an assumed 60 km/s dispersion in quadrature; the
supplied geko paper uses a radius-dependent pressure correction and a geometry
coefficient. These prescriptions are not interchangeable measurements.

## Why MCMC alone cannot repair the result

### The optimizer and sampler target different objectives

`KinematicsFitter.loss()` minimizes an unweighted R-minus-C sum of squares.
`log_likelihood()` uses a mask, spatially varying variance, a correlation
temperature, and a noise-scale parameter. The sampler additionally applies
priors. An Adam solution is therefore not generally a MAP for that posterior.
Ranking multistart solutions by the Adam score need not rank their posterior
probabilities correctly. One favorable pairwise check on ID16887 does not
establish equivalence for other points or sources.

For a defensible profile, fix the amplitude or the velocity at a chosen radius,
then optimize all nuisance parameters under **one common target** at every
point, using multiple starts. Three local minima at three amplitudes are not
a profile likelihood. A percentage change in unweighted SSE is not a
confidence interval.

### Rectification changes the noise with the trial velocity

Writing the two resamplers as A_R(theta) and A_C(theta), the residual is

\[
 r=A_R d_R-A_C d_C,
 \quad C_r=A_R C_R A_R^T+A_C C_C A_C^T
\]

for independent grism inputs. Even if the input covariance is diagonal,
resampling produces correlations and parameter-dependent variance.

`setup_noise_model()` computes diagonal variances and a scalar effective-pixel
factor at one fitted point, then freezes them while theta changes. This is a
working approximation, not the full correlated Gaussian likelihood. A single
temperature cannot generally correct every parameter's uncertainty. The
handoff's own validation reports amplitude widths about 3-4 times too small and
biased registration recovery. Those factors should not be applied universally
to different sources, masks, or revised estimators.

For unweighted SSE, the expected score contains both signal mismatch and
`trace(C_r(theta))`. Thus it can improve because interpolation smooths the
noise more strongly. Fixing C's offsets does not remove this effect.

A new fixed-nuisance scan of ID16887 found that outside radius 20 pixels the
observed residual SSE and the independent-input-noise prediction from the
bilinear weights have correlation **0.956** across V_rot=0-600 km/s. The
outer-aperture measured SSE ranged 0.0572-0.0788; the predicted noise term
ranged 0.0444-0.0638. This demonstrates a substantial changing noise term, not
that every local minimum is an artifact. The scan is **not a profile** and its
independent-input-noise assumption is itself approximate for stacked products.

The handoff's statement that the amplitude comb is an inevitable physical
one-pixel degeneracy is not established. An amplitude change produces a
spatially varying displacement, not a uniform integer translation. Numerical
pixel-phase effects need to be separated from actual observational degeneracy.

Left: saved ID3700 runs at two learning rates. Right: the new fixed-nuisance

### Detection significance and the pixel threshold are uncalibrated

At zero rotation, angle, center and turnover radius are unidentified. The
one-sided amplitude prior also places the null at a boundary. Ordinary Wilks
chi-square calibration therefore does not apply; using a tempered approximate
likelihood creates additional calibration problems. See
[Protassov et al.](https://arxiv.org/abs/astro-ph/0201547) and
[Davies](https://doi.org/10.1093/biomet/64.2.247).

Likewise, one dispersion pixel is a sampling scale, not a fundamental velocity
detection threshold. Subpixel shifts can be measured at sufficient S/N with a
validated instrumental model. STScI distinguishes dispersion sampling from
[grism spectral resolving power](https://jwst-docs.stsci.edu/jwst-near-infrared-camera/nircam-instrumentation/nircam-grisms).
Rejecting 8 km/s solely because it is subpixel is not justified; accepting it
because of the nominal Wilks significance is also not justified.

A negative rotating-minus-null score, as for the saved ID8910 result, proves
that the current rotating solution is not the maximum of its nested model.
It does not by itself produce a numerical upper limit. Lack of optimizer
convergence also cannot be relabeled as a scientific nondetection.

**Updated:** the clean notebook now reports exploratory model preference,
removes the one-pixel and nominal-Wilks detection gates, and saves
`model_prefers_rotation` and `detection_validated=False` instead of `rotates`.
Consumers of the old headline schema need that small adjustment. The legacy
statistics remain available in `compare_null_model`, with their limitations
documented. No archived detection verdicts or numerical products were rewritten.

### Inclination needs to enter the inference, not only the final division

Sampling V_sini helps numerical conditioning, but inclination also enters the
deprojected radius through cos(i). Fixing i, sampling the kinematics, and then
dividing by independently drawn sin(i) is only an approximation to marginalizing
over inclination. It misses changes in the fitted velocity field and its
covariance with R_v. This is especially relevant for inclined disks.

Use an imaging-derived inclination distribution, with disk thickness and
morphology mismatch treated explicitly, in joint inference or a grid of
conditional kinematic fits. The inherited 2.5-degree scatter has not been
independently calibrated for this sample.

If only the rising part of the curve is observed, V_sini/R_v can be much better
constrained than either asymptotic amplitude or turnover radius. Report V(r)
and the corresponding mass estimator over observed radii, retaining their
joint posterior; do not extrapolate a precise asymptotic speed from a local fit.

### Sampling and checkpoint issues still need work

The default walkers start in a small ball around Adam. Good acceptance and
short autocorrelation times can describe just one local mode. Independent
ensembles from distinct solutions and comparison of derived profiles are
needed. Burn-in reseeding based on log-probability height can discard alternate
modes before their probability mass is understood; it is not proof of discovery
of the globally important modes.

The checkpoint fingerprint hashes input images and some settings, but omits
actual frozen masks/variance/footprints, fixed parameter values such as the
adopted inclination, and calibration/geometry state. HDF backend resume checks
are weaker still. Reloading a saved chain rebuilds rather than restores its
exact frozen likelihood. Thus a changed fit can reuse an incompatible target
even with the same input files and parameter names. This remains **unfixed**;
keep new analyses in fresh checkpoint paths and retain `RESUME=False` until
likelihood state is saved and verified explicitly.

## The supplied paper and benchmark provenance

Section 5.2 and Figure 10 of `2503.15587v1.pdf` concern **ID3700**, z=1.123,
module B. They describe matching the distortion-corrected R/C maps, an arctan
disk, no fitted velocity dispersion, and MCMC, with details deferred. The
supplied original package has no MCMC implementation; this does not establish
whether a separate implementation was used for the paper.

I did not find ID15665's purported published V_sini=271.5 or dlnL=1278 in that
paper. The user does not have a separate reference implementation. Agreement
with those numbers should be treated as internal consistency until their
independent provenance is supplied. It does not validate the null statistic.

## GPU measurements and repair order

Short synchronized timings on the local RTX 4090, torch 2.14.1+cu130, used saved
real ID3700/ID16887 parameters. They measured likelihood callbacks, not complete
new chains:

| Operation | Time |
|---|---:|
| Batched likelihood/posterior, 16-128 points, 40 iterations | approximately 0.06 s |
| 16 separate scalar likelihood/posterior calls, ID3700 | approximately 1.00 s |
| 16-point batch, 80 iterations | approximately 0.12-0.13 s |

Two half-ensemble callbacks imply roughly 0.12 s per ensemble step, or about
20 minutes per 10000 steps before initialization, checkpointing and convergence
extensions. The old four-hour statement is not representative of this measured
batched path. GPU utilization and actual proposal validity can change timings.

On 16 nearby ID3700 parameter points, 10 and 20 iterations rejected all points
accepted at 80. Forty accepted all, with maximum log-likelihood difference
about 0.0054. ID16887 at 20 accepted all but differed by up to 0.135; at 40 the
difference was about 0.0052. This local test supports retaining 40, not a global
guarantee over the prior. Tiny repeated CUDA differences were also observed.

Recommended sequence:

1. **Reassess optimization on the current code.** Use a common objective, scaled
   parameters, complete saved states and all free gradients enabled. Retain
   the best iterate; never call worsening convergence. Profile projected
   velocity at observed radii, with multistarts over radius, angle, center and
   registration. Start with ID3700 and ID15665, then investigate ID21636. Do
   not require recovery of a preselected velocity as the success criterion.
2. **Build an exposure-aware joint forward likelihood.** Keep R and C separate
   and share a flexible emission-line map and velocity field. For exposure j,
   model d_j = A_j(theta, PSF, LSF) S + background/contamination + noise. Fit or
   marginalize S under an explicit, tested regularization; do not require the
   line morphology to equal a broadband Sersic fit. Calibration, pixel
   integration, line width and registration belong in A_j. This avoids
   continually warping the observed noise to compare two inverse reconstructions.
3. **Use the GPU for batches.** Keep `vectorize: true`; batch the initialization
   grid too, cache fixed grids/calibration and avoid scalar CPU transfers in
   inner loops. A direct forward projection avoids the present 40-step inverse
   solve. Profile before adding `torch.compile` or switching samplers: NUTS is
   useful only with reliable derivatives and does not remove multimodality.
4. **Validate before publishing profiles.** Fit independent exposure subsets,
   check held-out R and C residuals, test registration/PSF/LSF and inclination
   sensitivity, and assess uncertainty coverage with explicitly separate
   validation experiments. Calibrate detection/upper-limit procedures under
   the null. More iterations alone cannot repair likelihood misspecification.
5. **Produce radial posteriors.** Evaluate V(r), the chosen pressure/geometry
   mass model, and their correlated intervals only across an independently
   justified emission-line radial range. Show where posterior constraints
   become prior dominated. A source can have useful inner profiles without a
   determined asymptotic amplitude.

MCMC can stay within `fitting.py`, as requested in the earlier handoff. These
scientific repairs do not require a wholesale package reorganization.

## Changes and verification from this audit

Production changes are limited to gradient flags on stage entry, complete scan
state restoration and final scoring, the enclosed-mass helper/notebook call,
and honest notebook interpretation/timing. No optimizer rates, priors or source
data were retuned. Existing chains, handoff snapshots and results were retained.

The complete CPU test suite passed: **167 passed**, including three new
regressions. The notebook's code cells parse, and `git diff --check` passes.
The warnings are an existing tensor-to-scalar warning and two F480M calibration
spline warnings. Passing software tests does not establish scientific coverage.

Diagnostic scripts, the noise scan and exposure provenance are preserved in
`/home/aakavan/kinematics/results/2026-10-13_audit/`. No complete source refit or
new posterior has been claimed; the old amplitudes and detection classifications
remain provisional. In particular, neither the handoff's “ID3700 settled” nor
its “ID21636 intrinsically unmeasurable” conclusion follows from the flawed
restart experiment alone.
